# Визуализатор графа зависимостей npm

Вариант №28. Практическая работа №2 по дисциплине
«Конфигурационное управление», РТУ МИРЭА, ИКБО-40-25.

## Описание

Консольный (CLI) инструмент для анализа зависимостей пакетов
менеджера npm (JavaScript). Готовые менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются: программа
написана на Python только со стандартной библиотекой.

Все настройки задаются в конфигурационном файле формата INI.
Программа читает файл и проверяет все параметры; если они заданы
неверно, выводятся все найденные ошибки сразу. Затем программа
обращается к репозиторию пакетов npm по URL, получает данные о
последней версии заданного пакета и выводит все его прямые
зависимости.

## Требования

- Python 3.10 или новее

Сторонние библиотеки не используются.

## Запуск

    ./run.sh [--config PATH]

| Параметр | Описание |
|----------|----------|
| `--config PATH` | путь к конфигурационному файлу INI, по умолчанию `config.ini` |

## Конфигурационный файл

Параметры записываются в секции `[settings]`. Строки,
начинающиеся с `;` или `#`, — комментарии.

    [settings]
    package = express
    repository = https://registry.npmjs.org
    test_mode = false
    output = graph.svg
    filter = debug

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `package`    | да  | имя анализируемого пакета |
| `repository` | да  | URL-адрес репозитория пакетов или путь к файлу тестового репозитория |
| `test_mode`  | нет | режим работы с тестовым репозиторием: `true` или `false` (по умолчанию `false`) |
| `output`     | да  | имя файла, в который будет сохранено изображение графа |
| `filter`     | нет | подстрока: пакеты, в имени которых она есть, не анализируются (по умолчанию пусто) |

### Проверка параметров

- **`package`** — не пустое. В обычном режиме — допустимое имя пакета
  npm: строчные латинские буквы, цифры, `-`, `.`, `_`, `~`, не
  длиннее 214 символов, можно со scope (`@babel/core`). В тестовом
  режиме — большие латинские буквы (`A`, `B`, `AB`).
- **`repository`** — не пустое. В обычном режиме — адрес вида
  `http://…` или `https://…` с именем сервера. В тестовом режиме —
  путь к существующему файлу.
- **`test_mode`** — `true` или `false`; допускаются также
  `yes`/`no`, `on`/`off`, `1`/`0`.
- **`output`** — не пустое, оканчивается на `.svg`, не является
  каталогом, каталог для файла существует.
- **`filter`** — может быть пустым, но не должно содержать пробелов.

Ошибки самого файла: файл не найден, указан каталог, пустой путь,
файл не в UTF-8, нарушен формат INI (строка без `=`, параметры до
заголовка секции, повтор параметра или секции), нет секции
`[settings]`, неизвестная секция или параметр, не задан
обязательный параметр.

При ошибке программа выводит в поток ошибок список всех найденных
проблем и завершается с кодом 1. Неизвестный аргумент командной
строки — код 2.

## Получение зависимостей

Программа запрашивает документ пакета по HTTP API реестра npm:

    GET {repository}/{package}
    Accept: application/vnd.npm.install-v1+json

В имени со scope символ `/` кодируется: `@babel/core` →
`@babel%2Fcore`. Из ответа берётся последняя версия
(`dist-tags.latest`) и её поле `dependencies` — это прямые
зависимости пакета с диапазонами версий. Для запроса используются
только модули `urllib` и `json` стандартной библиотеки.

Выводятся все прямые зависимости, подстрока `filter` на этом этапе
не применяется. Режим тестового репозитория (`test_mode = true`)
будет поддержан на этапе 3, сейчас программа сообщает об этом.

| Ошибка | Сообщение |
|--------|-----------|
| пакета нет (ответ 404) | `ошибка: пакет не найден в репозитории: …` |
| другой код ответа | `ошибка: репозиторий вернул ошибку 500 для …` |
| сервер недоступен | `ошибка: не удалось подключиться к …` |
| ответ не JSON | `ошибка: ответ репозитория не является JSON: …` |
| в ответе нет последней версии | `ошибка: в ответе репозитория нет последней версии пакета …` |

Коды завершения: 0 — успешно, 1 — ошибка конфигурации,
2 — неверный аргумент командной строки, 3 — ошибка репозитория.

## Примеры использования

Прямые зависимости пакетов (вывод 23.10.2026):

    $ ./run.sh
    Пакет: express 5.3.0
    Прямые зависимости (28):
      accepts ^2.0.0
      body-parser ^2.3.0
      content-disposition ^2.0.1
      content-type ^2.0.0
      cookie ^0.7.1
      …

    $ ./run.sh --config configs/babel_core.ini
    Пакет: @babel/core 8.0.7
    Прямые зависимости (16):
      @babel/code-frame ^8.0.6
      @babel/generator ^8.0.6
      @babel/helper-compilation-targets ^8.0.7
      …

    $ ./run.sh --config configs/react.ini
    Пакет: react 19.3.1
    Прямых зависимостей нет

Зависимости выводятся по алфавиту. Номера версий зависят от
состояния реестра на момент запуска.

Пакет не найден:

    $ ./run.sh --config configs/fetch_errors/not_found.ini
    ошибка: пакет не найден в репозитории: https://registry.npmjs.org/no-such-package-depgraph-v28

Ошибки в нескольких параметрах:

    $ ./run.sh --config configs/errors/all_wrong.ini
    ошибка конфигурации:
      - package: недопустимое имя пакета npm: 'Bad Name'
      - test_mode: ожидается true или false, получено 'sometimes'
      - output: имя файла должно оканчиваться на .svg: 'graph.jpg'
      - filter: подстрока не должна содержать пробелов: 'a b'

## Сборка и тесты

Сборка не требуется: Python — интерпретируемый язык,
сторонние библиотеки не используются.

Модульные тесты:

    python3 -m unittest discover tests

Модульные тесты не обращаются к сети: ответы реестра в них
подменяются.

Скрипты ОС для демонстрации:

| Скрипт | Что показывает |
|--------|----------------|
| `scripts/test_config.sh` | правильные конфигурации и обработку ошибок для всех параметров |
| `scripts/test_deps.sh` | прямые зависимости нескольких пакетов и ошибки получения данных (нужен интернет) |
