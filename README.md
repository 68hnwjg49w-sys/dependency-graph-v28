# Визуализатор графа зависимостей npm

Вариант №28. Практическая работа №2 по дисциплине
«Конфигурационное управление», РТУ МИРЭА, ИКБО-40-25.

## Описание

Консольный (CLI) инструмент для анализа зависимостей пакетов
менеджера npm (JavaScript). Готовые менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются: программа
написана на Python только со стандартной библиотекой.

Все настройки задаются в конфигурационном файле формата INI.
Программа читает файл и проверяет все параметры; если они заданы
неверно, выводятся все найденные ошибки сразу. Затем программа
строит граф зависимостей заданного пакета с учётом транзитивности:
обходом в глубину (DFS, рекурсивно) получает зависимости пакета,
зависимости этих зависимостей и так далее. Пакеты, в имени которых
есть заданная подстрока, не анализируются. Циклические зависимости
находятся и выводятся отдельно, обход на них не зацикливается.

Источник данных — реестр npm по URL или, в режиме тестирования,
файл тестового репозитория, где пакеты называются большими
латинскими буквами.

## Требования

- Python 3.10 или новее

Сторонние библиотеки не используются.

## Конфигурационный файл

Параметры записываются в секции `[settings]`. Строки,
начинающиеся с `;` или `#`, — комментарии.

    [settings]
    package = express
    repository = https://registry.npmjs.org
    test_mode = false
    output = graph.svg
    filter = debug

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `package`    | да  | имя анализируемого пакета |
| `repository` | да  | URL-адрес репозитория пакетов или путь к файлу тестового репозитория |
| `test_mode`  | нет | режим работы с тестовым репозиторием: `true` или `false` (по умолчанию `false`) |
| `output`     | да  | имя файла, в который будет сохранено изображение графа |
| `filter`     | нет | подстрока: пакеты, в имени которых она есть, не анализируются (по умолчанию пусто) |

### Проверка параметров

- **`package`** — не пустое. В обычном режиме — допустимое имя пакета
  npm: строчные латинские буквы, цифры, `-`, `.`, `_`, `~`, не
  длиннее 214 символов, можно со scope (`@babel/core`). В тестовом
  режиме — большие латинские буквы (`A`, `B`, `AB`).
- **`repository`** — не пустое. В обычном режиме — адрес вида
  `http://…` или `https://…` с именем сервера. В тестовом режиме —
  путь к существующему файлу.
- **`test_mode`** — `true` или `false`; допускаются также
  `yes`/`no`, `on`/`off`, `1`/`0`.
- **`output`** — не пустое, оканчивается на `.svg`, не является
  каталогом, каталог для файла существует.
- **`filter`** — может быть пустым, но не должно содержать пробелов.

Ошибки самого файла: файл не найден, указан каталог, пустой путь,
файл не в UTF-8, нарушен формат INI (строка без `=`, параметры до
заголовка секции, повтор параметра или секции), нет секции
`[settings]`, неизвестная секция или параметр, не задан
обязательный параметр.

При ошибке программа выводит в поток ошибок список всех найденных
проблем и завершается с кодом 1. Неизвестный аргумент командной
строки — код 2.

## Получение зависимостей из реестра npm

Программа запрашивает документ пакета по HTTP API реестра npm:

    GET {repository}/{package}
    Accept: application/vnd.npm.install-v1+json

В имени со scope символ `/` кодируется: `@babel/core` →
`@babel%2Fcore`. Из ответа берётся последняя версия
(`dist-tags.latest`) и её поле `dependencies` — это прямые
зависимости пакета с диапазонами версий. Для запроса используются
только модули `urllib` и `json` стандартной библиотеки.

Для каждого пакета графа берётся его последняя версия: диапазоны
версий из `dependencies` не разрешаются. Каждый пакет запрашивается
у реестра один раз.

| Ошибка | Сообщение |
|--------|-----------|
| пакета нет (ответ 404) | `ошибка: пакет не найден в репозитории: …` |
| другой код ответа | `ошибка: репозиторий вернул ошибку 500 для …` |
| сервер недоступен | `ошибка: не удалось подключиться к …` |
| ответ не JSON | `ошибка: ответ репозитория не является JSON: …` |
| в ответе нет последней версии | `ошибка: в ответе репозитория нет последней версии пакета …` |

## Тестовый репозиторий

При `test_mode = true` параметр `repository` — путь к текстовому
файлу с описанием графа. Одна строка — один пакет и его прямые
зависимости через пробел; пакеты называются большими латинскими
буквами. Пустые строки и строки, начинающиеся с `#`, пропускаются.

    # Ромб: B и C зависят от D
    A: B C
    B: D
    C: D
    D:

Ошибки файла выводятся все вместе с номерами строк: строка без `:`,
имя пакета или зависимости не из больших латинских букв, пакет описан
повторно. Ошибка выводится также, если файл пуст или если при обходе
встретился пакет, который в файле не описан.

| Файл | Случай |
|------|--------|
| `repos/basic.txt`      | ромб: общая зависимость |
| `repos/chain.txt`      | длинная цепочка транзитивных зависимостей |
| `repos/single.txt`     | пакет без зависимостей |
| `repos/cycle.txt`      | цикл A → B → C → A |
| `repos/self_cycle.txt` | пакет зависит сам от себя |
| `repos/cycles.txt`     | два цикла в одном графе |
| `repos/filter.txt`     | пакеты для проверки фильтра |
| `repos/big.txt`        | граф побольше, многобуквенные имена, цикл |
| `repos/errors/*.txt`   | ошибки формата, неописанный пакет, пустой файл |

## Граф зависимостей

Граф строится рекурсивной функцией обхода в глубину (DFS) в
`src/graph.py`:

1. Пакет добавляется в граф и в текущий путь от корня.
2. Для каждой его прямой зависимости:
   - если имя содержит подстроку `filter`, зависимость пропускается
     и не анализируется — в граф не попадают ни она, ни пакеты,
     достижимые только через неё;
   - если зависимость уже есть на текущем пути, найден цикл: ребро
     сохраняется в графе, цикл запоминается, обход по ребру не идёт;
   - если зависимость ещё не обойдена, функция вызывается для неё
     рекурсивно; уже обойдённые пакеты повторно не обходятся.
3. Пакет убирается из текущего пути.

Пустой `filter` ничего не исключает. Если подстрока есть в имени
самого анализируемого пакета, выводится ошибка.

Программа выводит для каждого пакета его зависимости в порядке
обхода, число пакетов в графе, исключённые фильтром пакеты и
найденные циклы. Каждый цикл соответствует одному обратному ребру
обхода.

Коды завершения: 0 — успешно, 1 — ошибка конфигурации,
2 — неверный аргумент командной строки, 3 — ошибка получения данных
или построения графа.

## Примеры использования

Тестовый репозиторий с общей зависимостью:

    $ ./run.sh --config configs/test/basic.ini
    Граф зависимостей пакета A (обход в глубину):
      A -> B, C
      B -> D
      D -> нет зависимостей
      C -> D
    Пакетов в графе: 4
    Циклических зависимостей нет

Цикл:

    $ ./run.sh --config configs/test/cycle.ini
    Граф зависимостей пакета A (обход в глубину):
      A -> B
      B -> C
      C -> A, D
      D -> нет зависимостей
    Пакетов в графе: 4
    Циклические зависимости (1):
      A -> B -> C -> A

Фильтр `X`: пакеты XB и XC не анализируются, поэтому E, доступный
только через XB, в граф не попадает:

    $ ./run.sh --config configs/test/filter.ini
    Граф зависимостей пакета A (обход в глубину):
      A -> B, C
      B -> нет зависимостей
      C -> D
      D -> нет зависимостей
    Пакетов в графе: 4
    Исключены фильтром 'X': XC, XB
    Циклических зависимостей нет

Ошибки в файле тестового репозитория:

    $ ./run.sh --config configs/test/errors/bad_lines.ini
    ошибка: ошибки в файле тестового репозитория:
      - строка 3: ожидается запись «ПАКЕТ: ЗАВИСИМОСТИ»
      - строка 4: имя пакета — большие латинские буквы, получено 'c'
      - строка 5: имя зависимости — большие латинские буквы, получено 'e'
      - строка 6: пакет A описан повторно

Граф реального пакета из реестра npm (нужен интернет, вывод
29.10.2026):

    $ ./run.sh --config configs/debug.ini
    Граф зависимостей пакета debug (обход в глубину):
      debug -> ms
      ms -> нет зависимостей
    Пакетов в графе: 2
    Циклических зависимостей нет

Для express (`config.ini`) граф содержит 63 пакета. С фильтром
`debug` (`configs/express.ini`) пакет debug исключается, а ms
остаётся, потому что от него зависит и send:

    $ ./run.sh --config configs/express.ini
    Граф зависимостей пакета express (обход в глубину):
      express -> accepts, body-parser, content-disposition, …
      accepts -> mime-types, negotiator
      mime-types -> mime-db
      …
      send -> encodeurl, escape-html, etag, fresh, http-errors, …
      ms -> нет зависимостей
      …
    Пакетов в графе: 62
    Исключены фильтром 'debug': debug
    Циклических зависимостей нет

Пакет не найден:

    $ ./run.sh --config configs/fetch_errors/not_found.ini
    ошибка: пакет не найден в репозитории: https://registry.npmjs.org/no-such-package-depgraph-v28

Ошибки в нескольких параметрах:

    $ ./run.sh --config configs/errors/all_wrong.ini
    ошибка конфигурации:
      - package: недопустимое имя пакета npm: 'Bad Name'
      - test_mode: ожидается true или false, получено 'sometimes'
      - output: имя файла должно оканчиваться на .svg: 'graph.jpg'
      - filter: подстрока не должна содержать пробелов: 'a b'

## Сборка и тесты

Сборка не требуется: Python — интерпретируемый язык,
сторонние библиотеки не используются.

Модульные тесты:

    python3 -m unittest discover tests

Модульные тесты не обращаются к сети: ответы реестра в них
подменяются, графы проверяются на тестовых репозиториях.

Скрипты ОС для демонстрации:

| Скрипт | Что показывает |
|--------|----------------|
| `scripts/test_config.sh` | правильные конфигурации и обработку ошибок для всех параметров |
| `scripts/test_deps.sh` | графы пакетов из реестра npm, фильтр, ошибки получения данных (нужен интернет) |
| `scripts/test_graph.sh` | графы на всех тестовых репозиториях: общие зависимости, циклы, фильтр, ошибки |
